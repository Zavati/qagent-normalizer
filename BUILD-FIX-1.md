# QAgent Normalizer — Catalog Contract v1 Build Fix 1

## Symptom

Cloudflare build failed after `wrangler types` with:

```text
Property 'CATALOG_UPDATE_QUEUE' does not exist on type 'Env'.
```

The generated `Env` contained `NORMALIZER_DB`, `ENVIRONMENT`, and `SERVICE_NAME`, but no `CATALOG_UPDATE_QUEUE`.

## Root cause

The Catalog contract requires this producer binding in the active `wrangler.toml`:

```toml
[[queues.producers]]
binding = "CATALOG_UPDATE_QUEUE"
queue = "qagent-catalog-updates-dev"
```

A previous deployment instruction said to preserve `wrangler.toml` to retain the real D1 `database_id`. Keeping the entire older file also kept the older binding set, so the new Queue producer definition was lost.

## Fix

- Keep the new snapshot `wrangler.toml`.
- Copy only the real `NORMALIZER_DB.database_id` from the existing environment into the new file.
- Keep the `CATALOG_UPDATE_QUEUE` producer block.
- `worker-configuration.d.ts` is generated by Wrangler and is no longer shipped in the snapshot.
- Build now runs `verify:bindings` before `wrangler types` and fails with a targeted message if the Catalog producer binding is missing.

## Required producer binding

```toml
[[queues.producers]]
binding = "CATALOG_UPDATE_QUEUE"
queue = "qagent-catalog-updates-dev"
```

## Expected build sequence

```text
npm run build
  -> npm run typecheck
  -> npm run cf-types
  -> npm run verify:bindings
  -> wrangler types
  -> Env includes CATALOG_UPDATE_QUEUE: Queue
  -> tsc --noEmit
```
